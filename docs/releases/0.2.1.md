# OrbitFabric OpenC3 COSMOS Adapter 0.2.1

**Published:** 2026-09-25 as [GitHub Release v0.2.1](https://github.com/OrbitFabric/orbitfabric-openc3-cosmos-adapter/releases/tag/v0.2.1).

This post-migration patch normalizes active metadata and release Source Coordinate identity under `github.com/OrbitFabric:orbitfabric/openc3-cosmos@0.2.1`, publisher `orbitfabric`. No projection behavior or supported target-compatibility change is introduced.

## Change summary

- Preserve `verification_projection`, COSMOS-owned Python procedure/suite generation, and the existing target-specific binding and result semantics.
- Preserve the generic Result-owned `orbitfabric.scenario_projection_accounting` `0.1-candidate` sidecar added by `v0.2.0`; the contract maturity remains candidate.
- Keep the exact validated Core commit `b4e1185de4931ff125be699dfe09f63ab3746015` while acquiring the dependency from a commit-addressed HTTPS source archive rather than Git transport.
- Retain the validated OpenC3 COSMOS v7.3.0 lane and historical `v0.1.0` FAROTECH Source Coordinate, release bytes, locks and evidence unchanged.

## Evidence and acceptance boundaries

The GitHub Release and three publisher-owned assets are public. Existing hosted CI validates product behavior and exact COSMOS source/API compatibility. The external native COSMOS Script Runner acceptance remains a separate evidence gate; the earlier `v0.1.0` accepted runtime evidence is not silently reattributed as a fresh independent `v0.2.1` post-publication greenfield replay.

Publication does not promote Core-owned adapter lifecycle/integration contracts or the Scenario Projection Accounting contract from candidate maturity; no broader COSMOS version support or production deployment qualification is implied.
